TypeSpec describes your service API in a concise, reusable language. The Azure libraries add
shared patterns and checks for Azure API guidelines, and emitters turn your definition into
OpenAPI specifications and client libraries.

Use the stable package versions for your project. The `@next` channel contains prerelease
builds from `main`; current versions are listed on each package's npm page.

## Generate client libraries

Choose the emitter for your target language:

- [Python](./emitters/clients/typespec-python/reference/index.mdx)
- [JavaScript](./emitters/clients/typespec-ts/reference/index.mdx)
- [C#](./emitters/clients/typespec-csharp/reference/index.mdx)
- [Java](./emitters/clients/typespec-java/reference/index.mdx)
- [Go](./emitters/clients/typespec-go/reference/index.mdx)

Check <a href={baseUrl("/can-i-use/http/")}>SDK support</a> for scenario coverage across emitters.
For OpenAPI 3 output, see the [TypeSpec OpenAPI emitter](https://typespec.io/docs/emitters/openapi3/).

## How to get help

- Ask the [TypeSpec community on Discord](https://aka.ms/typespec/discord).
- [File an issue in the Azure repository](https://github.com/Azure/typespec-azure/issues).
  Include your TypeSpec code, expected and actual results, and any diagnostics.
- See [linter suppression guidance](./troubleshoot/suppresswarnings.md) when a guideline does not apply to your API.
