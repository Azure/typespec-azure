## 1. Introduction

We are replacing OAD (openapi-diff) with a TypeSpec-native API diff tool for TypeSpec-authored specs. This document correlates OAD's rule set with our tool's coverage at two levels:

1. **Diff detection** — Can our diff engine detect the same change that OAD detects? (Maps OAD rules to our `DiffKind` values)
2. **Breaking change classification** — When detected, how do we classify it in Phase B? (Maps to our named rules and severities)

**Important context:**

- In **Phase A** (same-version regression), ALL detected diffs are errors — including additive changes. OAD's `SameVersion` scenario is analogous.
- In **Phase B** (cross-version against previous stable), only certain diffs are classified as breaking. OAD's `CrossVersion` scenario is analogous.
- The table below focuses on Phase B classification for the "Breaking?" column.

## 4. Key Differences in Philosophy

- **Wire-level only**: Our tool only detects changes visible on the HTTP wire. OAD also detects OpenAPI structural changes (`allOf`, `$ref` redirections, definitions) and SDK-facing changes (`x-ms-enum`, `operationId`, LRO extensions).
- **Direction-aware**: Our tool distinguishes request vs. response context for type changes and property compatibility. OAD uses broader rules such as `TypeChanged` without the same request/response split.
- **Three-way type classification**: We separate incompatible format/type change, narrowing, and widening. Classification remains direction-aware, but non-breaking cases are ignored rather than surfaced separately.
- **Two-layer architecture**: Our tool separates diff detection (what changed?) from classification (does it matter?). OAD conflates detection with severity. Our tool uses a binary Error/Ignore severity model — there is no third severity tier. A change is either breaking (Error) or not reported at all (Ignore). OAD also supports configurable rule severity, but as a flat configuration rather than a context-dependent policy.
- **Phase A is stricter than OAD's SameVersion**: OAD's SameVersion still classifies changes by rule. Our Phase A treats ALL diffs as errors because modifying an existing version is never permitted without a new api-version.
- **No false positives from OpenAPI restructuring**: OAD reports `DifferentAllOf`, `ReferenceRedirection`, and `DifferentExtends`, which are often harmless restructurings. Our TypeSpec-native comparison operates on effective wire contracts.
